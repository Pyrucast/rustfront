# mtest-rs

Test an [MFront] behaviour at one material point: read a `.mtest` file,
impose strains (or deformation gradients) and stresses over time, write the
evolution of the strains, stresses and internal state variables in a `.res`
file.

> **mtest-rs is an unofficial, independent reimplementation in Rust of a
> subset of [MTest], which is part of TFEL.** It is built on
> [rustfront](https://crates.io/crates/rustfront). It is not affiliated with the TFEL project, CEA or EDF.
> It copies no code of MTest: it follows MTest's algorithm, as MTest's
> documentation, source and observed behaviour describe it.

It reads the same input files as MTest and writes result files with the same
columns, so that both can be compared: see `scripts/try.sh` and
`scripts/compare.py` at the root of the repository.

## Usage

```bash
mtest-rs tension.mtest                       # writes tension.res
mtest-rs tension.mtest --output other.res
```

```cpp
@ModellingHypothesis 'Tridimensional';
@Behaviour<generic> 'src/libBehaviour.so' 'Norton';
@MaterialProperty<constant> 'YoungModulus' 200e9;
@MaterialProperty<constant> 'PoissonRatio' 0.3;
@MaterialProperty<constant> 'NortonCoefficient' 5e-69;
@MaterialProperty<constant> 'NortonExponent' 8.2;
@ExternalStateVariable 'Temperature' 293.15;
@ImposedStress 'SXX' {0:0, 1:60e6};
@Times {0, 1 in 5, 100 in 20};
```

Components that are neither imposed a strain nor a stress are free, at zero
stress; in plane strain, `EZZ` is zero. As in MTest, off-diagonal components
are given and written multiplied by √2 (TFEL's convention).

A finite strain behaviour is driven by its deformation gradient, which starts
from the identity, and by its Cauchy stress: `FZZ` is one in plane strain,
and the components of F carry no √2. Each shear stress gives the equations of
two components of F (`SXY` those of `FXY` and `FYX`): one of each pair must
be imposed, usually all six off-diagonal components to zero.

## Supported keywords

| Keyword | Notes |
|---|---|
| `@ModellingHypothesis` | `Tridimensional` by default |
| `@Behaviour<generic>` | the `generic` interface only: small strain behaviours, finite strain ones, point-wise models |
| `@MaterialProperty<constant\|function>` | scalars |
| `@MaterialProperty<generic> 'name' 'library' 'law'` | a material property generated by MFront, evaluated at the external state variables named after its inputs, with the policy None |
| `@ExternalStateVariable[<evolution\|function>]` | scalars |
| `@ImposedStrain`, `@ImposedStress` `[<evolution\|function>]` | components `EXX`…`EYZ`, `ERR EZZ ETT ERZ`, `S…`; the Cauchy stress for finite strain |
| `@ImposedDeformationGradient` `[<evolution\|function>]` | components `FXX FYY FZZ FXY FYX FXZ FZX FYZ FZY`, `FRR FZZ FTT FRZ FZR` |
| `@InternalStateVariable` | initial value, `0` or `{…}` |
| `@Parameter`, `@IntegerParameter`, `@UnsignedIntegerParameter` | set when loading the behaviour, `b[0]` for an element of an array |
| `@OutOfBoundsPolicy` | `'None'`, `'Warning'` or `'Strict'` |
| `@Times` | `{0, 1 in 10, 2}` |
| `@Real` | a value or an expression, usable in functions |
| `@OutputFile`, `@OutputFilePrecision` | 6 digits by default |
| `@StrainEpsilon`, `@StressEpsilon` | `1e-12` and `1e-3` by default |
| `@MaximumNumberOfIterations`, `@MaximumNumberOfSubSteps` | `100` and `10` by default |
| `@Author`, `@Date`, `@Description` | ignored |

An evolution is a constant, a table `{t0:v0, t1:v1, …}` (linear in between,
constant outside), or with `<function>` an expression of `t`: numbers, `t`,
`@Real` constants, `+ - * / ^`, parentheses and `sin cos tan asin acos atan
sinh cosh tanh exp log ln log10 sqrt abs`.

## Differences with MTest

- Only small strain behaviours, finite strain ones and point-wise models of
  the `generic` interface.
- The residual of a finite strain behaviour is assembled as in TFEL's master
  branch: the MTest of TFEL 5.1 and before puts the diagonal of the stress in
  the rows of the shear. On the same results, it then makes one more
  iteration, and it cannot solve free shear components.
- No `@Test` (comparison with reference values), no JUnit report, no
  acceleration algorithms, no prediction policies, no rotation matrix, no
  pipe tests.

## Algorithm

The same as MTest's default one, so that both give the same results:

- the unknowns are the strain (or deformation gradient) components and one
  Lagrange multiplier per imposed component, scaled by the largest term of
  the first tangent operator;
- each step starts from the previous state (no prediction) and is solved by
  Newton iterations with the consistent tangent operator;
- an iteration has converged, never the first one, when its correction of
  the strain and its residual are below `@StrainEpsilon` and
  `@StressEpsilon`, and every imposed strain and stress is met;
- on failure, the step is halved, and kept halved until the next time of
  `@Times`.

On the cases of `cases/`, the results of mtest-rs and MTest 5.1.0 agree to
1e-12 relative, and both make the same number of iterations at every step,
finite strain aside (see above).
